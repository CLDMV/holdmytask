# HoldMyTask v2.0.4 Changelog

**Release Date**: October 2026
**Release Type**: Patch

---

## Overview

v2.0.4 makes the CommonJS entry fail clearly on Node.js versions that cannot `require()` an ES module, picks up a fix for a medium-severity denial-of-service advisory in `brace-expansion` (a development-time dependency), and moves two development tools forward. Behavior on supported Node.js versions is unchanged.

---

## 🐛 Bug Fixes

### CommonJS entry requires the ESM entry directly and fails clearly on older Node.js ([#48](https://github.com/CLDMV/holdmytask/pull/48))

`index.cjs` is a thin wrapper that loads `index.mjs` through Node's synchronous `require(esm)`. It now calls `require("./index.mjs")` directly instead of going through `createRequire`, and checks `process.features.require_module` first. On a Node.js version without `require(esm)` (before 20.19 and 22.12), `require("@cldmv/holdmytask")` used to die with a bare `ERR_REQUIRE_ESM`; it now throws an error with the same code and a message that names the supported versions (`^20.19.0` or `>=22.12.0`) and suggests loading the package with `import()` instead. On Node.js versions that support `require(esm)` the module resolves exactly as before. The new `tests/cjs/entry.test.cjs` runs under `node --test` (through the new `test:cjs` script, also part of `npm test` and `npm run coverage`) and checks that `require()` and `import` return the same object and that the error appears when `require(esm)` is disabled.

## 🔒 Security & supply chain

### brace-expansion 5.0.9 → 5.0.12 ([#44](https://github.com/CLDMV/holdmytask/pull/44))

Fixes [GHSA-q2hr-2g5m-vwhr](https://github.com/advisories/GHSA-q2hr-2g5m-vwhr) (CVE-2026-102277, medium, CVSS 5.3): expanding `{a},b}`-shaped input took quadratic time in the number of literal `}` characters, so an untrusted pattern could block the event loop. `brace-expansion` is a development-only dependency, pulled in solely by `minimatch` in the lint and test toolchain, and the package has no runtime dependencies, so the shipped code never loaded it. The update clears the open Dependabot alert on the lockfile.

## 🔧 Dependencies

- `@eslint/css` 1.4.0 → 2.0.0 (development; [#43](https://github.com/CLDMV/holdmytask/pull/43)). The major release adds `meta.languages` to the CSS rules. `npm run lint` passes unchanged with the repo's `css/recommended` configuration.
- `prettier` 3.9.6 → 3.9.9 (development; [#41](https://github.com/CLDMV/holdmytask/pull/41)). Lockfile-only: the `^3.0.0` range in `package.json` already allowed it.

## 🔧 CI & tooling

- The header comments in the generated `types/*.d.mts` files and their source maps were refreshed to the shared file-header format. Only comments changed; no type declarations differ from v2.0.3.

## Upgrade notes

No breaking changes — drop-in for [v2.0.3](./v2.0.3.md). The only runtime-visible difference is the clearer error for `require()` on Node.js versions that already could not load the package.
