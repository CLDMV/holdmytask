# HoldMyTask v2.1.2 Changelog

**Release Date**: November 2026
**Release Type**: Patch
**Branch**: `release/2.1.2`

---

## Overview

v2.1.2 is a development-tooling release. The test config now resolves the package through the `holdmytask-dev` export condition the way it was meant to, and the type scripts use the fleet names `types:check` and `types:build`.

No library code changed. The queue, its options and the published files are the same as in v2.1.1, and nothing changes for anyone installing the package.

---

## 🔧 CI & tooling

### Tests run against `src/` through `devCondition()` ([#99](https://github.com/CLDMV/holdmytask/pull/99))

`.configs/vitest.config.mjs` set `test.nodeOptions` to pass `--conditions=holdmytask-dev` to the test workers, but vitest has no such option, so the condition never reached them. The config now builds on `devCondition()` from `@cldmv/configs` (bumped to `^1.4.0`), which sets the resolver conditions and the worker `execArgv`, so Node's own resolver picks `src/` through the `holdmytask-dev` export condition too.

### Type scripts renamed to `types:check` and `types:build` ([#101](https://github.com/CLDMV/holdmytask/pull/101))

- `test:types` is now `types:check` (`tsc --noEmit` on `.configs/tsconfig.dts.jsonc`), and CI's type-check step runs it.
- `build:types` is now `types:build`, which emits the declarations. `build:ci` and `precommit` use the new names.
- The `.prettierignore` comment and the CI comments name the new scripts.
