# HoldMyTask v2.0.0 Changelog

**Release Date**: August 2026
**Release Type**: Major

---

## Overview

v2.0.0 makes `HoldMyTask` and its aliases the real class again at the package entry, fixes a scheduler deadlock, and replaces the generic `development` export condition with a package-specific one. The class change is a breaking change for code that adapted to the async factory functions that the entry exported in [v1.6.1](../v1/v1.6.1.md) and [v1.6.2](../v1/v1.6.2.md).

---

## 💥 Breaking Changes

### The package entry exports the class again ([#11](https://github.com/CLDMV/holdmytask/pull/11), fixes [#3](https://github.com/CLDMV/holdmytask/issues/3))

The default export and the named exports `HoldMyTask`, `queue`, `Queue`, `TaskManager`, `TaskQueue`, `QueueManager` and `TaskProcessor` are the `HoldMyTask` class, so `new HoldMyTask()`, `new Queue()` and the rest construct the same type. This is the shape [v1.6.0](../v1/v1.6.0.md) and earlier shipped; the async factories introduced in v1.6.1 are no longer behind those names. The `createHoldMyTask`, `createQueue`, `createTaskManager` and `createTaskProcessor` functions remain available as named async exports. `index.cjs` receives the class as well. The previously skipped Common Aliases tests are enabled again.

### Development export condition renamed

The `./main` export now selects `src/` through the `holdmytask-dev` condition instead of the generic `development` condition, so an application that happens to run with `--conditions=development` can no longer flip this package onto a source tree it does not ship. Only source checkouts are affected; the published package contains `dist/` only.

### `./devcheck` subpath export removed ([#12](https://github.com/CLDMV/holdmytask/pull/12))

`@cldmv/holdmytask/devcheck` pointed at `devcheck.mjs`, which is not part of the published package, so the export could never resolve for a consumer.

## 🐛 Bug Fixes

### Scheduler deadlock when a ready task's delay expires mid-reschedule ([#8](https://github.com/CLDMV/holdmytask/pull/8))

A task already sitting in the ready heap could be left stranded when nothing else scheduled a recheck: the next run time stayed at infinity and the scheduler fell through to its 24.8-day fallback timer. The scheduler now forces an imminent recheck in that case, and only in that case, so an active future delay keeps its single efficient timeout. A regression test covers it in `tests/BypassDelayCompletionTiming.test.vitest.mjs`.

### Development check corrected ([#12](https://github.com/CLDMV/holdmytask/pull/12))

`devcheck.mjs` now matches the `holdmytask-dev` condition exactly, reading it from both `process.execArgv` and `NODE_OPTIONS` and accepting `--conditions=…`, `--conditions …` and `-C …`. It no longer consults `NODE_ENV`, and it skips itself when the package is installed under `node_modules`. The warning text explains the condition and how to set it. A new `tests/DevCheck.test.vitest.mjs` covers these cases.

## Upgrade notes

If you were on [v1.6.0](../v1/v1.6.0.md) or earlier, the entry behaves as before. If you adopted the factory form in v1.6.1 or v1.6.2 by calling the default import as a function (`await createHoldMyTask(opts)`), that call now fails because the default export is a class; use `new HoldMyTask(opts)`, or import the named `createHoldMyTask` function, which still returns a promise. Anything that set `--conditions=development` to load `src/` from a checkout must switch to `--conditions=holdmytask-dev`.
