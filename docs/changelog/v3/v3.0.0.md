# `@cldmv/holdmytask` v3.0.0 Changelog

**Release Date**: November 2026
**Release Type**: Major
**Branch**: `release/3.0.0`

---

## Overview

v3.0.0 switches the CommonJS entry to the generic `index.cjs` shim used across the CLDMV libraries. `require("@cldmv/holdmytask")` now returns the module object, the same exports `import` gives, instead of the `HoldMyTask` class with the aliases attached as properties.

This is the only breaking change, and it only affects code that uses `require()` and treats the result as the class. ESM `import` is unchanged, and so is the queue itself.

---

## 💥 Breaking Changes

### `require("@cldmv/holdmytask")` returns the module object ([#116](https://github.com/CLDMV/holdmytask/pull/116), fixes [#115](https://github.com/CLDMV/holdmytask/issues/115))

The ESM entry exports several distinct values: the `HoldMyTask` class (also exported as `default`, `queue`, `Queue`, `TaskManager`, `TaskQueue`, `QueueManager` and `TaskProcessor`) and the four `create*` factories. With more than one distinct value, the shim hands back the module object:

```javascript
const holdmytask = require("@cldmv/holdmytask");
// => { default, HoldMyTask, queue, Queue, TaskManager, TaskQueue, QueueManager, TaskProcessor,
//      createHoldMyTask, createQueue, createTaskManager, createTaskProcessor }

const { HoldMyTask } = require("@cldmv/holdmytask");
const queue = new HoldMyTask();
```

- `new (require(x))()` becomes `new (require(x).HoldMyTask)()`, or `const { HoldMyTask } = require(x)`.
- Anything read off the class through the result, such as `require(x).someStatic`, goes through `.HoldMyTask`.
- `require(x).HoldMyTask`, `.queue`, `.Queue`, `.TaskManager`, `.TaskQueue`, `.QueueManager` and `.TaskProcessor` keep working, and destructuring them works as before.
- `require(x).default`, `createHoldMyTask`, `createQueue`, `createTaskManager` and `createTaskProcessor` are newly available.

`src/index.cjs` is now the same small file as in other CLDMV libraries (Node version guard, then `require("./index.mjs")`), and the build still copies it unchanged to `dist/index.cjs`. The CommonJS entry test expects the module object and checks that every export matches the ESM entry.

## 🔧 CI & tooling

- `ci.yml` adopts the CLDMV/.github v4.46.0 concurrency block, so superseded runs on `next`, `hotfixes` and the release PRs are cancelled ([#117](https://github.com/CLDMV/holdmytask/pull/117), fixes [#114](https://github.com/CLDMV/holdmytask/issues/114)).
- `ci.yml` is synced with the v4.43.0 template, so the release PR no longer reruns the matrix on a commit its push run already tested ([#112](https://github.com/CLDMV/holdmytask/pull/112)).
- The `sync-release-notes.yml` companion workflow is added ([#110](https://github.com/CLDMV/holdmytask/pull/110)).
- New `test:dist` script builds the package and runs the vitest suite against `dist/`, and `npm test` now includes it ([#103](https://github.com/CLDMV/holdmytask/pull/103)).

## Upgrade notes

- `require("@cldmv/holdmytask")` no longer returns the `HoldMyTask` class. Use `const { HoldMyTask } = require("@cldmv/holdmytask")`, and read anything class-level through `HoldMyTask`.
- The existing alias names work as before; `default` and the `create*` factories are new.
- ESM `import` is unchanged.
