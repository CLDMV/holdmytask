# HoldMyTask v1.4.0 Changelog

**Release Date**: November 2025
**Release Type**: Minor

---

## Overview

This release makes task metadata and coalescing information available directly on the task handle returned by `enqueue()`, and adds methods for inspecting coalescing groups from the queue.

---

## ✨ Features

### Direct metadata and coalescing info on task handles

Every task handle, whether it is the callback-style handle or the Promise returned when no callback is given, now exposes a `metadata` property with the metadata attached at enqueue time and a `coalescingInfo` property. `coalescingInfo` is `null` for tasks that are not coalesced; for coalesced tasks it contains `coalescingKey`, `groupId`, `representativeId`, `taskCount` and `allTaskMetadata` (an array of `{ id, metadata }` for every task in the group). Both properties stay readable after the task has finished, so there is no need to look the task up again to get at its metadata.

```javascript
const task = queue.enqueue(async () => "task completed", {
	metadata: { userId: 123, action: "save", document: "report.pdf" },
	coalescingKey: "user-actions"
});

console.log(task.metadata);
console.log(task.coalescingInfo.taskCount);
```

### Coalescing group inspection methods

Four new queue methods make it possible to look at coalescing groups without holding a reference to an individual task: `getCoalescingGroup(coalescingKey, groupId?)` returns the details of one group (or all groups for a key when `groupId` is omitted), `getCoalescingGroupMetadata(coalescingKey, groupId?)` returns `{ taskId, groupId, metadata }` entries for the tasks in those groups, `getCoalescingGroupsSummary()` returns `{ groupCount, totalTasks }` per coalescing key, and `findCoalescingGroupByTaskId(taskId)` returns the group (and the task's own details) that contains a given task. TypeScript declarations for all four are included.
