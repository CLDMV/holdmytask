# HoldMyTask v1.3.0 Changelog

**Release Date**: November 2025
**Release Type**: Minor

---

## Overview

This release adds a unified configuration system for priorities and coalescing keys, task lookup by ID, async construction, and a set of familiar queue aliases. Several older options are deprecated in favor of the new ones and emit `warning` events.

---

## ✨ Features

### Priority and coalescing configuration

A new `priorities` option sets per-priority timing (`{ [priority]: { postDelay, startDelay } }`), and a new `coalescing` option holds `defaults` plus per-key overrides under `keys`. Settings can also be changed at runtime with `configurePriority()` and `configureCoalescingKey()`, and read back with `getPriorityConfig()`, `getPriorityConfigurations()`, `getCoalescingConfig()`, and `getCoalescingConfigurations()`. The default coalescing window is 200 ms and the default maximum delay is 1000 ms. Within these configs, `delay` and `start` are still accepted and mapped to `postDelay` and `startDelay`.

### Custom task IDs and lookup

`enqueue()` accepts an `id` option, and enqueueing a second task with an ID that already exists is rejected. Tasks can be looked up with `get(id)` and `has(id)`, and `cancel(id, reason?)` now returns `true` when a pending task was cancelled and `false` otherwise. `getTask`, `hasTask`, and `cancelTask` remain as aliases.

### Async construction

Passing `sync: false` to the constructor defers initialization to the next tick and makes `new HoldMyTask({ ... })` return a Promise that resolves to the queue.

### Aliases

`schedule()` and `add()` are aliases for `enqueue()`, and `shutdown()` is an alias for `destroy()`. The class is also exported under the names `queue`, `Queue`, `TaskManager`, `TaskQueue`, `QueueManager`, and `TaskProcessor`, and as the default export.

### Unlimited queue size

Setting `maxQueue: -1` is now treated as unlimited, equivalent to `Infinity`.

### Deprecation warnings

Using a deprecated option now emits a `warning` event of type `deprecation`, with the old name and its replacement. The deprecated options are `delays` (use `priorities`), the four top-level `coalescing*` options (use `coalescing.defaults.*`), and the `start` and `delay` properties inside priority and coalescing configs (use `startDelay` and `postDelay`). All of them continue to work in this release.

## 🔧 CI & tooling

- Internal methods now use an underscore prefix (for example `_startTask` and `_scheduleNextTick`) to separate them from the public API.
- New test suites cover the aliases, async construction, and the enhanced configuration, bringing the suite to 165 tests.

## Upgrade notes

Existing code keeps working; deprecated options still apply and only emit `warning` events, so attach a `warning` listener to see them and migrate to `priorities` and `coalescing` at your own pace. Two behavior changes to be aware of: `enqueue()` on a destroyed or full queue (or with a duplicate `id`) no longer throws synchronously — it returns a rejected Promise and emits an `error` event — and the CommonJS entry now exports the class itself as `module.exports`, with `HoldMyTask` and the aliases attached as properties, so `const { HoldMyTask } = require(...)` continues to work.
