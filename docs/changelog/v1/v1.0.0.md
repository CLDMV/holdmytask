# HoldMyTask v1.0.0 Changelog

**Release Date**: November 2025
**Release Type**: Major

---

## Overview

Initial release of HoldMyTask, a tiny, dependency-free task queue for Node.js that runs tasks in priority order with concurrency control and configurable completion delays.

---

## ✨ Features

### Priority-based execution with concurrency control

Tasks are queued with a numeric `priority` (higher runs first) and executed up to a configurable `concurrency` limit. Queue behavior is tuned through constructor options such as `defaultPriority`, `maxQueue`, `tick`, and `autoStart`, and the queue can be controlled with `pause()`, `resume()`, `clear()`, `size()`, `inflight()`, and `destroy()`.

### Completion delays and delay bypass

The `delays` option maps a priority to a delay (in milliseconds) that is applied after a task of that priority completes, holding back newly starting tasks. A task can override the delay with its own `delay` option, and urgent tasks can skip an active delay with `bypassDelay: true` (or `delay: -1`).

### Callback and Promise APIs

`enqueue(task, callback?, options?)` accepts an optional `(error, result)` callback; when the callback is omitted it returns a Promise that also carries the task handle (`id`, `cancel()`, `status()`, `startedAt`, `finishedAt`, `result`, `error`). Both styles can be mixed on the same queue.

### Timeouts and cooperative cancellation

Each task receives an `AbortSignal`, and a per-task `timeout` cancels tasks that run too long. An external `signal` can be passed in to cancel a task, and queue activity is reported through the `start`, `success`, `error`, `cancel`, and `drain` events.

### Packaging

The package ships both ESM and CommonJS entry points, TypeScript declarations, and has no runtime dependencies. A `@cldmv/holdmytask/main` export resolves to the source files in development and the built files in production, and a `@cldmv/holdmytask/devcheck` export provides a development-environment check.
