# HoldMyTask v1.6.2 Changelog

**Release Date**: August 2026
**Release Type**: Patch

---

## Overview

v1.6.2 moves the repository onto the CLDMV v4 staging-branch release workflow and the shared `@cldmv/vitest-runner` test setup, and refreshes the development toolchain. No runtime code changed: nothing under `src/`, `index.mjs`, `index.cjs` or `devcheck.mjs` is touched.

---

## 🔧 CI & tooling

### v4 release workflow ([#5](https://github.com/CLDMV/holdmytask/pull/5))

The `.github/workflows/` set for the v4 flow was added (CI, publish, next and hotfixes release, release notifications, CodeQL, dependency review, scorecard, CLA, labeler, stale, tag health and the rest), together with a `.github/dependabot.yml` that targets `next`.

### Test runner

Test files were renamed from `*.vest.mjs` to the shared `*.test.vitest.mjs` naming convention and are now run through `tests/run-vitest.mjs` and `@cldmv/vitest-runner`. The vitest configuration anchors its project root to the package directory, raises the test timeout to 30 seconds, uses the `dot` reporter, and collects `v8` coverage for `src/**`. New scripts: `test:watch`, `coverage`, `ci:coverage`, `lint:fix`, `format` and `format:check`.

The Common Aliases test file was marked `describe.skip` for this release. It assumed `HoldMyTask` and its aliases are constructors, but the package entry exported async factory functions under those names at the time ([#3](https://github.com/CLDMV/holdmytask/issues/3)). It was un-skipped in [v2.0.0](../v2/v2.0.0.md) once that was resolved.

## 🔧 Dependencies

- Development dependencies were moved forward: `eslint` 10, `@eslint/js` 10, `@eslint/json` 2, `@eslint/markdown` 8, `@eslint/css` 1.4, `@html-eslint/*` 0.64, `typescript` 7, `vitest` and `@vitest/ui` 4.1, and `globals` 17. `@cldmv/vitest-runner` and `@vitest/coverage-v8` were added.

---

## Upgrade notes

No breaking changes in this release. Note that the package entry still exports async factory functions rather than the class, as it did in [v1.6.1](./v1.6.1.md); see the upgrade notes there and in [v2.0.0](../v2/v2.0.0.md).
