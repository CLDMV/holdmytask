# HoldMyTask v1.6.0 Changelog

**Release Date**: November 2025
**Release Type**: Minor

---

## Overview

This release adds per-priority concurrency limits, so each priority level can have its own cap on simultaneously running tasks while the global `concurrency` limit still applies.

---

## ✨ Features

### Per-priority concurrency limits

Entries in the `priorities` option now accept a `concurrency` value alongside `postDelay` and `startDelay`. A task starts only when both the global limit and its priority's limit allow it. When one priority is at its limit, the scheduler looks further through the ready tasks and starts a task of another priority that still has room, instead of stalling the queue. Priorities without a `concurrency` setting fall back to the global limit, so existing configurations behave as before.

```javascript
const queue = new HoldMyTask({
	concurrency: 8, // Global maximum across all priorities
	priorities: {
		1: { concurrency: 1, postDelay: 100 }, // Critical: only 1 at a time
		2: { concurrency: 3, postDelay: 200 }, // Important: up to 3 at a time
		3: { concurrency: 5, postDelay: 0 } // Background: up to 5 at a time
	}
});
```

### Per-priority concurrency in inspection output

`inspect()` and `inspectScheduler()` now include a `priorityConcurrency` object with `running`, `limit` and `available` for each priority that is currently running tasks or has a configured `concurrency`, and `debugLog()` prints a "Priority Concurrency" section when any are present.

---

## 📚 Documentation

The README documents `concurrency`, `postDelay` and `startDelay` under the `priorities` option, adds a "Per-Priority Concurrency Limits" section with configuration, usage and monitoring examples, and the TypeScript declarations and JSDoc are updated. A new test file, `tests/PerPriorityConcurrency.vest.mjs`, covers the feature.

## Upgrade notes

No breaking changes — drop-in for the previous version.
